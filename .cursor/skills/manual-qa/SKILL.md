# Manual QA — Task Tracker

## When to use

После implement фич доски/авторизации/задач или по явной просьбе пользователя прогнать ручной QA.

## Prerequisites

1. `docker compose up` — сервисы `db`, `backend`, `frontend` healthy.
2. UI: http://localhost:5173
3. API health: http://localhost:8000/api/health → `{"status":"ok"}`

Предпочитай browser tools (navigate → snapshot → click) если доступны; иначе пройди чеклист и отметь, что UI недоступен агенту.

## Checklist

Отмечай каждый пункт `PASS` / `FAIL` / `SKIP` с краткой причиной при FAIL.

### Auth

1. Регистрация нового email → попадание на доску текущей недели.
2. Выход → логин тем же пользователем → доска снова доступна.
3. Неверный пароль → понятная ошибка на русском.

### Неделя и доска

4. Открыта текущая неделя (Пн–Пт); текущий день визуально выделен.
5. «Предыдущая» / «Следующая» / «Текущая неделя» меняют диапазон и задачи.
6. Desktop: видны 5 колонок дней.

### Задачи

7. Создать задачу (описание, важность, опциональный дедлайн) → появляется в дне.
8. Отметить выполненной **без перезагрузки** → зачёркивание и кнопка «Вернуть».
9. Снять отметку → снова «Выполнено».
10. Soft-delete → задача в «Удалённые»; восстановление возвращает на доску.
11. Поиск по описанию фильтрует; сброс возвращает полный список.

### Перенос и порядок

12. Desktop DnD: перенос между днями меняет день карточки; дедлайн не меняется.
13. Desktop DnD: изменение порядка в дне сохраняется после обновления недели.
14. Mobile (≤767px): видна одна колонка; переключатель дней работает; «Перенести» через модалку.

### Реактивность (обязательно)

15. Toggle done → UI обновляется без F5.
16. После сдвига недели на mobile видна колонка (сегодня если в неделе, иначе первый workday / выбранный день).
17. Цели: добавить / отметить / удалить — блок целей обновляется без F5.
18. Дашборд недели отражает total/done после toggle задачи.

### Изоляция

19. Второй пользователь не видит задачи первого (если проверяешь двумя аккаунтами).

## Report format

```markdown
## Manual QA report
- Environment: docker compose, URL …
- Result: PASS | FAIL (N failed)

| # | Item | Status | Notes |
|---|------|--------|-------|
| 1 | … | PASS/FAIL/SKIP | … |

### Failures
- #N: steps to reproduce, expected vs actual
```

## Rules

- Не меняй код во время QA, кроме явного follow-up на найденные баги.
- Не коммить.
- UI copy и ошибки — на русском; сокращения только в названиях дней недели.
