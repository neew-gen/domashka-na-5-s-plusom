# Инструкции для AI-агента

## 1. Общие правила

- Перед выполнением задачи сначала изучи относящуюся к ней документацию проекта.
- Не начинай изменять код, пока не понял требования задачи.
- Реализуй только то, что требуется текущей задачей или текущей фазой.
- Не реализуй функциональность следующих фаз заранее.
- Не усложняй решение без необходимости.
- Проект является MVP, поэтому предпочитай простые и понятные решения.
- Следуй существующей архитектуре и стилю проекта.

## 2. Документация проекта

Основная документация находится в директории `docs/`.

Требования проекта:

`docs/requirements.md`

Планы реализации:

- `docs/01-infrastructure.md`
- `docs/02-backend.md`
- `docs/03-frontend.md`

Если пользователь просит реализовать конкретную фазу, сначала прочитай
соответствующий файл плана.

Документация проекта является источником требований.
Не придумывай новые требования самостоятельно.

## 3. Контекст репозитория

Если существует файл:

`.repomix/project.xml`

используй его для первичного знакомства со структурой существующего проекта.

Используй Repomix для:
- понимания структуры проекта;
- поиска нужных модулей;
- определения файлов, связанных с задачей;
- уменьшения количества файлов, которые необходимо читать полностью.

Repomix является только снимком проекта и может быть устаревшим.

Перед изменением файла обязательно прочитай его оригинальное содержимое.

Оригинальные файлы проекта являются источником истины.

## 4. Актуальная документация библиотек

При работе со сторонними библиотеками используй Context7, если необходимо
уточнить:

- API библиотеки;
- актуальный способ использования;
- конфигурацию;
- рекомендуемые паттерны;
- поведение конкретной версии;
- устаревшие API;
- особенности интеграции библиотеки.

Используй версии зависимостей, указанные в проекте.

Не обновляй библиотеку только потому, что существует более новая версия.

Не полагайся исключительно на знания модели, если поведение библиотеки
можно проверить по актуальной документации через Context7.

## 5. Работа с кодом

Перед изменением существующего кода:

1. Найди связанные с задачей файлы.
2. Прочитай их оригинальное содержимое.
3. Определи существующие архитектурные паттерны.
4. При необходимости проверь документацию сторонних библиотек через Context7.
5. Только после этого вноси изменения.

Не создавай новый abstraction/service/repository/helper, если существующая
структура проекта уже предоставляет подходящее место для реализации.

Не добавляй новую зависимость, если задача разумно решается существующими
средствами проекта.

## 6. Backend

Сохраняй существующее разделение ответственности между:

- router;
- service;
- repository;
- schemas;
- models.

Не помещай бизнес-логику в FastAPI routers.

Работу с базой данных выполняй через существующий слой доступа к данным.

Следуй используемому в проекте стилю SQLAlchemy 2.x.

При изменении моделей базы данных учитывай необходимость Alembic migration.

## 7. Frontend

Следуй существующей структуре компонентов.

Не помещай всю логику страницы в один большой компонент.

Работу с backend API выполняй через существующий API/data-access слой.

При изменении server state используй существующий подход TanStack Query.

Не добавляй новый state manager без необходимости.

## 8. Проверка изменений

После реализации задачи выполни относящиеся к ней доступные проверки.

Для backend это могут быть:

- pytest;
- ruff;
- проверка Alembic migrations.

Для frontend:

- lint;
- type checking;
- tests;
- build.

Не утверждай, что тест, линтер или build успешно прошёл, если команда
фактически не запускалась.

Если проверку невозможно выполнить, явно сообщи об этом.

## 9. Работа с ошибками

Если после изменения проверка завершилась ошибкой:

1. Проанализируй причину.
2. Исправь проблему.
3. Повтори проверку.

Не изменяй тест только для того, чтобы скрыть ошибку реализации.

Если тест противоречит актуальным требованиям проекта, сначала укажи
на это противоречие.

## 10. Завершение задачи

После выполнения задачи кратко сообщи:

- что было реализовано;
- какие основные файлы были изменены;
- какие проверки были запущены;
- прошли ли проверки;
- использовался ли Context7 и для каких библиотек;
- остались ли известные проблемы или ограничения.
