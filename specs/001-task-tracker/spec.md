# Feature Specification: Task Tracker MVP

**Feature Branch**: `001-task-tracker`

**Created**: 2026-10-09

**Status**: Draft

**Input**: User description: Трекер рабочих задач на неделю по ТЗ Артема (`docs/requirements.md` + `docs/qa.md`)

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Auth and weekly task board (Priority: P1)

Зарегистрированный пользователь входит в систему, видит текущую рабочую неделю (понедельник–пятница) с выделенным текущим днём, создаёт задачи с описанием, важностью и опциональным дедлайном, отмечает выполнение, переключает недели.

**Why this priority**: Без доски и базового CRUD нет продукта.

**Independent Test**: Регистрация → логин → создание задачи на сегодня → toggle выполнено → переход на прошлую/следующую неделю.

**Acceptance Scenarios**:

1. **Given** новый email, **When** регистрация и логин, **Then** открывается текущая неделя, текущий день выделен.
2. **Given** авторизованный пользователь, **When** создаёт задачу (описание, важность, опциональный дедлайн), **Then** задача появляется в выбранном дне.
3. **Given** задача не выполнена, **When** пользователь отмечает выполнение, **Then** текст зачёркнут; повторный клик снимает отметку.
4. **Given** открыта текущая неделя, **When** пользователь листает недели, **Then** отображаются задачи соответствующей недели (Пн–Пт, без выходных).

---

### User Story 2 — Drag-and-drop, trash, search (Priority: P2)

Пользователь перетаскивает задачи между днями и меняет порядок в дне; удаляет в «Удалённые» с восстановлением и очисткой; ищет задачи.

**Why this priority**: Ключевые сценарии ТЗ после базовой доски.

**Independent Test**: DnD на другой день; soft-delete → restore; поиск по описанию.

**Acceptance Scenarios**:

1. **Given** задача в понедельник, **When** перетаскивание на среду, **Then** меняется дата задачи в шапке карточки; дедлайн не меняется.
2. **Given** список задач дня, **When** перетаскивание вверх/вниз, **Then** порядок сохраняется.
3. **Given** задача, **When** удаление, **Then** она в «Удалённые»; восстановление в исходный или выбранный день; полная очистка раздела возможна.
4. **Given** несколько задач, **When** поиск, **Then** остаются совпадения по описанию.

---

### User Story 3 — Week goals and dashboard (Priority: P3)

Пользователь задаёт цели недели, отмечает их вручную; видит дашборд недели (счётчики + кольцо). Незавершённые цели переносятся на следующую неделю.

**Why this priority**: Завершает ТЗ (цели + статистика).

**Independent Test**: Добавить цель → отметить → сменить неделю и увидеть перенос незакрытой; дашборд считает задачи текущей недели.

**Acceptance Scenarios**:

1. **Given** неделя, **When** добавлена цель, **Then** она видна в блоке целей с возможностью отметить выполненной.
2. **Given** незакрытая цель, **When** открыта следующая неделя, **Then** цель перенесена.
3. **Given** задачи недели, **When** открыт дашборд, **Then** показаны всего / выполнено / не выполнено / процент и кольцевая диаграмма.

---

### Edge Cases

- Просроченная задача (день прошёл, не выполнена) — красный текст; без автопереноса.
- Дедлайн после переноса задачи на более поздний день — не меняется, предупреждений нет.
- Выполненные задачи можно переносить; остаются на месте в списке дня.
- Пользователь видит только свои данные.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST поддерживать регистрацию и вход одного пользователя на аккаунт; данные изолированы по пользователю.
- **FR-002**: Система MUST показывать рабочую неделю Пн–Пт; текущая неделя по умолчанию; текущий день выделен; навигация по прошлым/будущим неделям.
- **FR-003**: Задача MUST иметь описание, важность (низкая/средняя/высокая), опциональный дедлайн, дату дня, статус выполнена/не выполнена (вручную), дату создания (не акцентировать в UI).
- **FR-004**: Система MUST позволять перенос задач DnD между днями/неделями и сортировку внутри дня; на узких экранах — упрощённый перенос.
- **FR-005**: Удаление — soft-delete в «Удалённые»; восстановление в исходный или другой день; полная очистка раздела.
- **FR-006**: Поиск по описанию задач.
- **FR-007**: Цели недели независимы от задач; ручной статус; перенос незакрытых на новую неделю.
- **FR-008**: Дашборд недели: всего, выполнено, не выполнено, процент, кольцевая диаграмма; статистика по текущему расположению задач.
- **FR-009**: Просрочка: красный текст; без автопереноса и отдельного раздела.

### Key Entities

- **User**: email, password hash
- **Task**: description, importance, task_date, deadline?, is_done, position, deleted_at?, created_at, user_id
- **WeekGoal**: text, week_start (Monday), is_done, user_id

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Новый пользователь за ≤ 3 минуты регистрируется и создаёт первую задачу на текущем дне.
- **SC-002**: Перенос задачи на другой день сохраняется после перезагрузки страницы.
- **SC-003**: Дашборд отражает актуальные счётчики после toggle/переноса/удаления.
- **SC-004**: UI на русском; без сокращений кроме дней недели; важность полными словами с приглушённым цветом.
